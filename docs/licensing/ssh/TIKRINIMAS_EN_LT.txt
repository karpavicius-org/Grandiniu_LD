The final distribution ZIP is signed with the project Ed25519 key after the final Word and PDF documents are included. The detached .sig file and verification kit are supplied separately. The signature covers every byte of that ZIP, including the documents inside it.

This is a new project key created for revision 1.1 in the task execution environment, not a previously authenticated personal key of Rimas Karpavičius. An encrypted private-key backup is saved in the designated Drive folder. Its new passphrase is delivered separately and is excluded from the public folder, distribution archives and Git.

The previous project key is superseded because a passphrase-named file was found publicly readable. Its contents were not read. Do not use the previous fingerprint to authenticate this revision; the old and new fingerprints are recorded in KEY_REVOCATION.json.

Compare the fingerprint with one obtained through a trusted independent channel. The signature verifies content integrity and use of the corresponding key. The project label in allowed_signers does not independently certify a person's identity, legal ownership or a trusted timestamp. Historical Git commit signatures are unchanged.

Place the ZIP and the extracted verification files in the same folder. On Linux or macOS run the following command; an SSHSIG-capable ssh-keygen is required.

Windows: use TIKRINTI.cmd. Linux/macOS: you may use sh TIKRINTI.sh. Success means Good and exit code 0; any other result is a failed verification. The Windows command script was reviewed but was not executed on this Linux host.
