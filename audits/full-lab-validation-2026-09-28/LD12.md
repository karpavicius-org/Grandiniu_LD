# LD12 auditas — studento UI → dėstytojo UI

Data: 2026-09-28
Audituotas main prieš šį checkpointą: aa1aea684d5b3c62a319988ac365af41df01be4a

## Būsena

Virtualus LD12 yra trifazės simetrinės grandinės laboratorija:
- žvaigždės jungimas;
- trikampio jungimas;
- Uf = Ul/√3;
- fazinės ir linijinės srovės;
- Il = √3·If;
- žvaigždės ir trikampio galios palyginimas.

Pagrindinis C++ trifazės modelis matematiškai nuoseklus ir tiesiogiai grąžina žvaigždės / trikampio teorines reikšmes. Tačiau studento→ataskaitos→graderio evidence sluoksnyje yra svarbus neatitikimas: rubrika deklaruoja 7 matavimo kriterijus, nors realus studentas atlieka tik 2 matavimus.

Pagal oficialų dalyko numeravimą ši tema yra oficialus LD13, ne oficialus LD12.

Funkcinis kodas šiame etape nekeistas.

## Patvirtinta kaip veikianti

- Studentas realiai sujungia dvi topologijas:
  - žvaigždę;
  - trikampį.
- Abiejų režimų laidai saugomi atskirai.
- Laidų keitimas blokuojamas esant įjungtam trifaziam šaltiniui.
- Perjungiant režimą maitinimas ir jungiklis išjungiami.
- Wiring pakeitimas anuliuoja susijusio režimo evidence.
- Trifazis C++ modelis kind 6 skaičiuoja:
  - UfY = Ul/√3;
  - IfY = Ul/(√3·R);
  - UfΔ = Ul;
  - IfΔ = Ul/R;
  - IlΔ = √3·IfΔ;
  - PY;
  - PΔ = 3·PY.
- Testai patvirtina PΔ = 3·PY ir IlΔ = √3·IfΔ.
- Pavyzdys izoliuoja studento būseną ir nustato practice_used=true.
- Generic snapshot mechanizmas techniškai palaiko LD12.
- Targeted testai vykdo variantus 1, 17 ir 64, žvaigždę/trikampį, realius MNA rodmenis, report export, draft restore, 39 geometrijos atvejus ir 140 graderio palyginimų.

## CRITICAL / GRADING EVIDENCE — 7 matavimo kriterijai sukuriami iš tik 2 studento matavimų

Realiame LD12 studentas gali užfiksuoti tik:
1. vieną pasirinktos fazės matavimą žvaigždėje;
2. vieną pasirinktos fazės matavimą trikampyje.

ld12_measure() aiškiai sako:
„Režimui užtenka vieno fazės matavimo (simetrinė grandinė)“.

Be to, jei tame pačiame režime jau yra žurnalo eilutė, antras fazės matavimas neleidžiamas.

Tačiau bench_report_data("LD12") iš šių dviejų eilučių sukuria septynis observations:

Žvaigždėje:
- i1s = tas pats vienas žurnalo matavimas;
- i2s = tas pats vienas žurnalo matavimas;
- i3s = tas pats vienas žurnalo matavimas.

Trikampyje:
- i1d = tas pats vienas žurnalo matavimas;
- i2d = tas pats vienas žurnalo matavimas;
- i3d = tas pats vienas žurnalo matavimas.

Papildomai:
- ild nėra studento matavimas;
- jis į reportą įrašomas funkcija ld12_line_current(), kuri tiesiai kviečia C++ modelį ir grąžina teorinę linijinę srovę.

Taigi iš 7 graderio „matavimo“ kriterijų:
- 2 remiasi realiais studento matavimo veiksmais;
- 4 yra tų pačių dviejų matavimų kopijos kitoms simetrinėms fazėms;
- 1 yra tiesiogiai modelio sugeneruota reikšmė.

Tai nėra skaitinė fizikos klaida — simetrinėje grandinėje fazės iš tiesų vienodos. Problema yra vertinimo semantika:

> studentui negalima skirti septynių nepriklausomų matavimo kriterijų taip, lyg jis būtų atlikęs septynis matavimus, jei realiai atliko du.

Vėliau reikės metodinio sprendimo:
- arba rubrikoje matavimus vertinti kaip 2 realius eksperimentinius veiksmus;
- arba UI leisti / reikalauti realiai išmatuoti visas fazes ir linijinę srovę;
- arba aiškiai pažymėti sintetinius simetrijos kriterijus kaip 0 balų diagnostiką.

## CRITICAL — normalus LD12 paleidimas nėra assessment režimas

ld12_student_main() sukuria objektą be assessment=true.
ld12_init_state() taip pat nenustato assessment.

Todėl bench_report_data("LD12") normalų studento report eksportuoja kaip mode="learning".

Net pilnai teisingas darbas nepatenka į galutinę dėstytojo pažymių suvestinę.

## CRITICAL — studento UI neturi assessment / learning pasirinkimo

Bendra bench_mode("LD12") funkcija egzistuoja, bet LD12 Pagalbos meniu jos nekviečia.

Studentui pasiekiama:
- Kaip sujungti;
- Žemėlapis;
- Pavyzdys;
- Ataskaita;
- Atkurti stendą;
- Iš naujo.

Formalaus atsiskaitymo režimas per realų UI nepasiekiamas.

## CRITICAL / METHODIC — primary visada tikrina teisingumą

ld12_student_primary() nenaudoja assessment būsenos.

Jis visada kviečia ld12_check_step() ir neleidžia pereiti, kol atsakymas neatitinka etalono.

Todėl dabartinis LD12 yra mokymosi stendas su savikontrole, o ne formalus atsiskaitymo stendas, galintis perduoti klaidingą raw atsakymą dėstytojui.

## HIGH — CI ranka įjungia assessment tik prieš report export

studentui/tests/workflows.sci po pilno, teisingai išspręsto workflow daro:

LD12.assessment=%t

tik prieš galutinį report export.

Todėl tools/test_ld12.py gali teisingai patikrinti, kad eksportuotos ataskaitos yra mode=assessment ir selected_for_summary=true, nors realus studento startas assessment niekada neįjungia.

Tai tiesiogiai maskuoja produkto starto problemą.

## HIGH — realiame LD12 nėra autosave produkto srauto

Shared bench_session mechanizmas LD12 palaiko.

Tačiau realiame paleidime:
- autosave_enabled nenustatomas;
- callbackai nekviečia bench_autosave("LD12");
- Pagalboje nėra automatinio juodraščio atkūrimo.

Testai autosave_enabled=%t nustato ranka.

Todėl close/autosave/restore testas nėra realaus studento produkto kelio įrodymas.

## HIGH / TRACEABILITY — virtualus LD12 yra oficialus LD13

Oficialiame dalyko apraše:
LD13 = „Trikampiu ir žvaigžde jungiamų imtuvų tyrimas“.

Virtualus repo LD12 yra būtent šis darbas.

Dabartinis mokytojas ZURNALAS.csv virtualaus LD12 pažymį deda į stulpelį LD12, o oficialus LD13 stulpelis lieka tuščias.

Todėl dabartinės ZURNALAS.csv antraštės negali būti interpretuojamos kaip oficialių 13 laboratorinių darbų numeriai.

## HIGH / UI — paleidimo tekstas nukopijuotas iš RLC laboratorijos

ld12_start() rodo:
„sujunkite nuoseklią RLC grandinę“.

LD12 išvis nėra RLC laboratorija. Tai trifazė žvaigždės / trikampio laboratorija.

Studentui tai yra tiesiogiai klaidinantis pirmasis pranešimas.

## HIGH / UI — 2 etape rodomas literalus R = %g Ω

ld12_step_instruction(2) grąžina paprastą tekstinę eilutę su:

R = %g Ω

bet nenaudoja msprintf ir nepaduoda cfg.R.

Todėl studentas mato literalų „%g Ω“ vietoje savo varianto varžos.

## HIGH / UI — mA formulėse praleista ×1000 konversija

2 etapas:
If = Uf/R (mA)

4 etapas:
If = Ul/R (mA)

V/Ω rezultatas yra amperai. Norint gauti mA reikia dauginti iš 1000.

C++ modelis ir graderis tai daro teisingai. Klaida yra studento matomame paaiškinime.

5 etapo galios formulės yra nuoseklios, jei srovė naudojama mA:
V·mA = mW.
Tačiau būtų naudinga tai aiškiai pasakyti, kad nebūtų maišomos A ir mA formulės.

## HIGH / UI — komponento kortelėje rodomas literalus <br>

Šaltinio tekstas generuojamas:

3~ <Ul> V<br>50 Hz

naudojant Scilab text valdiklį.

Šis valdiklis <br> neinterpretuoja kaip HTML, todėl studentui rodomas literalus fragmentas.

## MEDIUM / UI — neteisingi fazės mygtukų numeriai klaidos pranešime

Tikrieji fazės mygtukai registre yra:
- B12;
- B13;
- B14.

Instrukcijos ir stendo žemėlapis teisingai nurodo [B12]–[B14].

B15 registre neegzistuoja.

## MEDIUM / UI — voltmetro kortelės tooltipas vadina ją vatmetru

LD12 GUI komponentų sąraše:
- k=7 yra VOLTMETRAS.

Tačiau k=7 tooltip nustatomas:
„Vatmetras: aktyrioji galia P...“

LD12 šiame UI vatmetro apskritai neturi.

Tai kopijavimo klaida iš LD11.

## MEDIUM — config failo komentaras yra iš visai kito RLC darbo

studentui/LD12/ld12_config.sci antraštė vis dar aprašo:
- nuoseklią RLC grandinę;
- L ir C;
- Q.

Faktinis kodas turi tik Ul ir R trifaziam darbui.

Vykdymo tai negadina, bet klaidina palaikant / audituojant sistemą.

## MEDIUM — pavyzdys pažymi practice_used, bet būsimam assessment reikės aiškios politikos

ld12_toggle_solution() nustato practice_used=true.

Tai gerai.

Tačiau jei formalus assessment bus įjungtas, pavyzdžio naudojimas turi būti:
- blokuojamas assessment metu; arba
- aiškiai pažymėti bandymą kaip neįskaitinį.

Restartas iš naujo inicializuoja būseną, todėl būsimo assessment metu reikia apsispręsti, ar practice žyma gali būti nunulinta pradėjus „iš naujo“ tą patį variantą.

## MEDIUM — README nurodo neegzistuojantį LD12/VARIANTAI.csv

LD12/VARIANTAI.csv

Dabartiniame main šio failo nėra.

Taigi README nuoroda į repo failą šiuo metu neatitinka realybės.

## Bendri dėstytojo UI radiniai

LD12 taip pat paveikia:
- ldcheck ir mokytojas --ui skirtinga submission konfliktų semantika;
- skirtingas studento grupavimo raktas;
- potencialus mokytojas --ui HTML/XSS per vardą/grupę;
- studento savarankiškai deklaruojama tapatybė ir numeris.

## LD12 audito išvada

Trifazės fizikos branduolys yra tvarkingas, tačiau LD12 turi svarbiausią iki šiol rastą rubrikos evidence neatitikimą:

> 7 matavimo balai nėra 7 realūs studento matavimai; penki jų sukuriami dubliuojant simetrinės grandinės reikšmę arba tiesiai iš modelio.

Be to reikia spręsti:
1. learning-only produkto srautą;
2. CI rankinį assessment įjungimą;
3. realaus autosave nebuvimą;
4. virtualaus LD12 ↔ oficialaus LD13 numeraciją;
5. kelias matomas UI/formulių klaidas.

Šiame etape niekas netaisyta.
